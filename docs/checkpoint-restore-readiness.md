The native-probe, single-phase reconstruction, and converted-verification host runners now use the same pinned `Wait-RetainedProbeRestored` helper after their initial selected/prepared restore and final baseline restore. Each invocation has a 30-second monotonic polling deadline, at most 31 observations, and sleeps of at most one second. Existing synchronous Hyper-V queries are not cancelled if a query itself stalls; the deadline prevents additional polling and rejects a result obtained after expiry.

Initial restores require the exact owned VM, off state, selected parent, fixed 8 GiB, generation 2, Secure Boot on, and disconnected networking before the existing Start action can execute. Baseline completion first observes the exact owned VM off on the baseline parent, then performs the existing memory reset only if necessary, and finally requires the full guard with fixed 4 GiB. The helper never retries Restore or memory changes, never starts or stops the VM, and never sets workflow-success flags.

Each observation is appended to `restoreReadinessObservations` and persisted through the existing create-new progress records. It includes workflow phase, expected parent/memory, VM ID, observed state/parent/memory, elapsed time, timestamp, readiness, and any query or guard error. A deadline, persistent mismatch, evidence-write failure, or memory-set failure propagates to the existing `failed-preserved` path. No historical run is promoted to success.
