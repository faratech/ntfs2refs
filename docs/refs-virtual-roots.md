# Bounded ReFS virtual-root translation

`src/refs_virtual_roots.rs` resolves the ten virtual checkpoint roots for the exact ReFS 3.14, 4 KiB-cluster, CRC64 profile. The production bootstrap inspector supplies checksum-accepted checkpoints and container walks from the same stable read-only handle. Per checkpoint, both container roots must finish, match their declared row counts, retain matching page checksums/headers, and contain identical mappings and raw values. Their physical roots and CRCs are bound back to that checkpoint's descriptors. A rejected or missing copy prevents translation for that checkpoint; another checkpoint cannot supply its map.

The implemented formula is `PLCN = map[VLCN >> 15] + (VLCN & 0x3fff)`. Bit 14 must be zero; container IDs are direct map keys, not vector indices. The wider shift is intentional. Missing containers, overflow, unsupported cluster units, duplicate/overlapping physical container ranges, and malformed descriptors are refused. This independently implements the documented field formula; no GPL implementation code was incorporated. [Primary container research](https://xbpt.gitlab.io/forefst/structures/container_table/)

The reader follows indices 0–6 and 9–11 only, using their documented table IDs. Four clusters are assembled in descriptor order, including noncontiguous slots. It checks full-page CRC64/NVME, `MSB+` version 2, reserved/header volume fields, all four self **virtual** slots and the expected table ID. Translated clusters cannot overlap any observed bootstrap/container page or another root in the same checkpoint. No node row or child reference is interpreted. [Checkpoint identities](https://xbpt.gitlab.io/forefst/structures/chkp/), [checksum references](https://xbpt.gitlab.io/forefst/structures/page_references/), [page headers](https://xbpt.gitlab.io/forefst/structures/page_header/)

The hard ceiling is twenty 16 KiB reads: **327,680 bytes**. Shared pages are reread for each checkpoint instead of cached, with `repeated_physical_page_reads` reported separately from `pages_read`; `reused_page_reads` is always zero. Complete page hashes, CRC results, per-slot translations, both mapping-row indices and a common-map digest are retained. Malformed roots remain explicit rejected observations; I/O failures propagate. No authoritative checkpoint is selected, and metadata, allocation, conversion and boot qualifications are unchanged.

## Native evidence and tests

Before implementing the reader, a separate small Rust helper applied the researched formula to the pinned 52 GiB Dev Drive capture. All twenty references passed CRC, self-location and table-ID comparisons. Both checkpoints name the same ten physical pages. Examples are object root 0 at physical clusters 15872–15875 (CRC `7162a6c1d4aad2bf`), schema root 3 at 68–71 (`0c877aef45a792ad`) and container-index root 10 at 52–55 (`4302cccc585c8fbc`). The helper, twenty small page files, observation log and SHA-256 list are under `.lab/research/refs-virtual-roots-20261024/`.

The opt-in native test then exercised production integration and matched every fetched page to those independent range hashes: twenty reads, ten repeated physical pages, 327,680 virtual-root bytes, and 832 identical container mappings in each checkpoint pair. It checks the pinned earlier inspection hash and raw image length without rehashing 52 GiB. Eleven synthetic tests cover map disagreement/incompleteness, checkpoint binding, reserved address bits, bounds, alias/overlap, checksum/header/table differences, read budgets and truncation. This is address-translation evidence for the captured sample, not allocation ownership or native writer acceptance.
