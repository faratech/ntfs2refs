# Current critical-volume policy for partition conversion

The partition path uses the documented Windows Storage Management partition roles, native Windows/pagefile/configured-dump extent checks, actual volume locking and persistent target-only protection. It does not claim to inspect undocumented loaded dump-driver internals. The loaded-driver diagnostic remains false.

Fresh source admission requires a complete, bracketed MSFT_Partition observation cross-bound to native partition identity/geometry. The selected mounted Basic partition must explicitly report IsBoot=false and IsSystem=false. Current Windows and known boot/system partitions must resolve to actual native extents outside the selected partition. Missing, NULL, incorrectly typed or inconsistent required properties refuse. During the intentional private-type phase, a missing management catalog row is accepted only after native identity independently proves that same private target; it is represented as None, never invented false. Readonly native collectors continue to verify Windows, every active paging-file location and configured/potential dump destinations. The actual original volume must successfully lock/dismount before any target type/attribute setter.

The same supported current-role facts are revalidated for private owners, shadow source metadata witnesses, fresh AP, MIXED recovery and terminal restoration. Comparisons retain actual critical bindings while allowing only the expected selected Basic/BasicRO/private transition. Whole-disk source paths and their guards remain unchanged.

Legacy VDS is diagnostic telemetry. IVdsVolume::GetProperties may return VDS_S_PROPERTIES_INCOMPLETE without identifying which fields are unavailable. Such rows retain raw HRESULT, IDs, status, health, type, size, name and flags but are explicitly UNCLASSIFIED. Zero/ordinary-looking partial flags do not establish a noncritical volume. The software-provider catalog can also omit EFI partitions, so it cannot supply mandatory positive system-volume coverage. No partial row or serialized diagnostic constructs source, writer or restoration authority.

The actual corrected readonly diagnostic on the prepared Windows VM enumerated seven volumes; every opening and closing call returned 0x00042715. The current C row showed boot/page/crash bits but no row reported the VDS SYSTEM bit. That observation explains the old gate's unconditional refusal; it is not itself a safety exception or native conversion qualification. The new collector and actual end-to-end source conversion still require native qualification.

Microsoft documents [MSFT_Partition boot/system properties](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/msft-partition), [partial VDS property returns](https://learn.microsoft.com/en-us/windows/win32/api/vds/nf-vds-ivdsvolume-getproperties), and [volume locking](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_lock_volume). Volume locking fails for a system/page-file volume and flushes cached data; process-held locking alone is not persistent isolation. Persistent private/readonly target state and authenticated recovery remain required.
