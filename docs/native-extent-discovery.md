# Native extent and bitmap discovery

`lab/guest/Capture-GuestExtentDiscovery.ps1` and `NativeExtentDiscovery.cs` collect bounded read-only native volume observations on the exact enrolled Windows 11 Dev Drive data profile. They do not create files on the target, move extents, format, issue raw disk I/O, change policy or qualify conversion. Mounted reads may still cause ordinary filesystem access-metadata activity.

The guest accepts `ControlRunId`, `ControlEvidenceSha256`, `CapturedAllocationSha256` and a new `DiscoveryId`. It binds the saved control and allocation evidence to the guest build/driver, original target enrollment, GPT identities, 52 GiB partition, 512-byte logical sectors, 4 KiB clusters and original 4 MiB patterned fixture. Existing fixture hashes, legacy 64-bit IDs and retrieval mappings are compared before and after the queries. Host orchestration is in `scripts/Invoke-LabExtentDiscovery.ps1`; it is lab infrastructure, not a converter dependency.

The native helper opens only the exact Storage-provider volume GUID with `GENERIC_READ` and read/write sharing. Its six synchronous calls are retrieval base before, legacy bitmap before, extended bitmap flags zero, extended bitmap flag one, retrieval base after and legacy bitmap after. Each base response is bounded to eight bytes; each bitmap response to 2 MiB. Query inputs, ABI sizes, native errors, byte counts, times and raw buffer hashes remain distinct.

Legacy bitmap input is eight zero bytes for starting LCN zero. Extended input is sixteen bytes: starting LCN at offset zero, flags at offset eight and four zero padding bytes. The WDK documents flag one as including metadata, but its acceptance and coverage must be measured for each profile. A difference between sequential results can also reflect intervening filesystem activity. [Extended input](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-starting_lcn_input_buffer_ex), [bitmap contract](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_volume_bitmap)

The parser requires starting LCN zero and the exact measured cluster count. Partial buffers are recorded as incomplete, never silently extended or truncated into a usable physical map. It counts occupied/free bits, compares complete buffers, samples known payload and separately labeled raw-metadata-cluster-as-LCN positions, and lists at most eight observed-free candidate ranges. Candidates are observations, not reservations; metadata coverage and raw address equivalence remain false.

The retrieval base is measured in sectors. Any candidate byte offset uses checked `base * sector_size + LCN * cluster_size` arithmetic and remains an address hypothesis until independently matched to unique raw payload bytes. Matching one fixture does not establish all metadata address translations. [Retrieval base](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_retrieval_pointer_base), [Microsoft cluster-address caveat](https://learn.microsoft.com/en-us/windows/win32/fileio/clusters-and-extents)

Output is a new `C:\ntfs2refs\extent-discovery\<DiscoveryId>` directory. Its at-most-nine-file allowlist is `discovery.json`, `allocation-before.json`, `allocation-after.json` (each at most 1 MiB), `baseBefore.bin`, `baseAfter.bin` (1–8 bytes each), and four `bitmap*.bin` files (each at most 2 MiB). Zero-byte native responses produce no buffer file. The aggregate export bound is 12 MiB; all bytes are verified after transport.

Completed native errors use `observed-with-unresolved-results`; successful bounded observations use `observed-awaiting-offline-payload-match`. Guard failures after output creation use `blocked`. Early preflight or transport failure may have no final record. The host preserves indeterminate branches, exports completed evidence before clean shutdown and returns to the exact baseline only after validation. Physical mapping, movement support, payload-copy avoidance and conversion remain unqualified by these records.

`lab/Test-GuestExtentDiscovery.ps1` tests pure parsers, malformed buffers, checked address arithmetic, bitmap comparisons and mocked/saved guest guards. It performs no native volume controls or VM operations. The original reviewed implementation passed 80 checks under Windows PowerShell 5, including saved native evidence.
